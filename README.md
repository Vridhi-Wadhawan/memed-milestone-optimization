# Milestone optimization for Meme'd campaigns

Give it a campaign (category, platform, creator tier, budget, planned number of creators) and it returns a four-rung milestone ladder: view thresholds and payouts. It also tells you the chance of staying within budget, how many creators should reach each rung, and warns when it is unsure.

Everything runs on synthetic data I generated, because there is no Meme'd data. Read the results as a test of the method, not as evidence about real campaigns.

## Read first

| File | What it is |
|---|---|
| `one_pager.md` | Plain-language summary for a brand manager or founder |
| `methodology.md` | What "optimized" means, the model, the assumptions, the limits |
| `outputs/backtest_report.md` | Backtest on all 100 campaigns (generated by the code) |

## Setup

Python 3.10 or newer.

```bash
pip install -r requirements.txt
```

## Run

```bash
# A ladder for a new campaign (takes a few seconds)
python run.py
python run.py --category finance --platform youtube --tier mid --budget 400000 --creators 60
python run.py --help

# Sanity tests
python tests/test_ladder.py

# Rebuild everything from scratch
python src/generate_data.py    # synthetic data, fixed seed
python src/validate.py         # model validation
python src/backtest.py         # 100 campaigns, about 2.5 minutes
python src/make_charts.py      # needs backtest.py first
python src/sensitivity.py      # about 5 minutes, optional
```

The data and outputs are already in the repo, so `run.py` works straight away. The scripts above regenerate them.

## Layout

```
run.py                     ladder for one new campaign
src/generate_data.py       synthetic campaigns, creators, posts, manual ladders
src/model.py               view model, simulation, ladder search
src/backtest.py            leave-one-campaign-out backtest and cold-start test
src/validate.py            out-of-sample checks on the view model
src/sensitivity.py         what changes if my judgement calls change
src/make_charts.py         charts for the one-pager
tests/test_ladder.py       sanity tests
demo_colab.ipynb           optional Colab wrapper (set REPO_URL in the first cell)
data/                      campaigns, creators, posts, milestone_ladders (CSV)
outputs/                   backtest, validation and sensitivity results, charts
```

## Things I added to the schema

`campaigns.csv` has an extra `expected_creator_count` column, because total payout depends on how many creators join.

## Main limits

The generator and the model share the same structure, so the backtest is friendlier than real data will be. Budgets and paid-media CPMs are invented. See section 10 of `methodology.md`.
